## 旧版问题和根因

| 用户发现 | 实际位置或缺口 | 可通过脚本解决 | 依赖外部能力或人审 |
|---|---|---|---|
| 1. 六页像 PPT | 旧 `render_story.py` 的 `background()` 一图复用；`render_frame()` 仅改同一机位中的少量物体，缺页级构图表 | 可以加入分镜和主体占画比校验 | 新分镜插画须生成并由视觉导演选稿 |
| 2. 乌鸦动作不连续 | 旧 `crow_state()` 直接切换少数姿态并长时间静止，缺接触前后中间姿态 | 时间线、脚底与嘴尖锚点可脚本化 | 足量且一致的关键姿态须图像生成与逐帧人审 |
| 3. 石子交互不完整 | 旧 `render_frame()` 用三段孤立抛物线，石子与嘴尖、罐口、水面未共享一条状态机 | 本样片实现单石唯一状态、口部锚点、入罐、下沉、水位后升 | 接触准确与运动可信度须动作导演看正常播放 |
| 4. 主体与文字偏小 | 旧角色在 1080 宽画面中占比低，正文 `stroke_paths(...,57)`，标题/页码固定 | 近景构图、主体框与手机安全区尺寸可控制 | 手机实际界面可读性须视觉导演确认 |
| 5. 中文旁白机械 | 旧 `sound_design.py` 只合成音乐与音效；旧 `audio-sources.json` 明确无 TTS。旧片**没有旁白**，故“机械旁白”不是对该文件的实测结论 | 可做停顿/读稿/混音时间线 | 当前无中文 TTS 模型或工具；两种自然试听 BLOCKED，需授权来源和人耳选声 |
| 6. 音乐廉价 | 旧 `sound_design.py` 使用连续正弦和弦与稀疏钟音，几乎没有旋律发展 | 本样片的八音正弦旋律仅作管线测试；可分离 music stem 不能签发品质 PASS | 风格、情绪和授权仍需声音导演试听、核对来源 |
| 7. 声音缺独立听感验收 | 旧 `verify_output.py` 只有电平、静音和编码检查 | 分离 music/foley/mix 与技术量测 | 旁白、音乐、音效及总混音四次人工试听不可由 ffprobe 替代 |
| 8. 技术 PASS 被当发布 PASS | 旧 `verify_output.py` 汇总 `overall_technical_pass`，没有发布级联动阻断 | 新 `publish_gate.py` 明确六个分立状态与证据哈希 | 主观导演记录必须由实际审阅者签署 |
| 9. 缺导演验收 | 旧 `review/acceptance.json` 是制作方自述，没有视觉/动作/声音导演签名和证据 | 可强制 reviewer 与文件 SHA-256 | 三类独立审阅者需要真实看片、听音 |
| 10. 发布物料不完整 | 旧交付只有 MP4、源码和 QA，缺封面、标题、笔记、版权台账 | 可生成物料模板与格式校验 | 标题、封面和权利范围须编辑审定 |

## 发布级 S0–S9 契约

| 阶段 | 输入 → 输出 | 质量门槛 | FAIL / BLOCKED |
|---|---|---|---|
| S0 选题与改写 | 原故事、目标读者 → 故事稿、来源说明 | 情节完整、原创中文改写、适龄 | 无来源/权利说明 BLOCKED；改写失真 FAIL |
| S1 剧本与分镜导演 | 故事稿 → 每页动作、镜位、时长、情绪、声音 cue 表 | 六页构图有远中近景变化，每页一个可见因果动作 | 只有换字幕或同一构图重复 FAIL |
| S2 角色和画风冻结 | 角色设定 → identity sheet、背景/道具分层源 | 体型、眼、喙、羽色、围巾与画风稳定；手机主角尺寸合格 | 错脸、残影、素材权利不明 BLOCKED |
| S3 动作关键姿态 | identity sheet、动作表 → 接触前/接触/离手/结果姿态 | 口部、脚底和道具锚点连续；物品不重影 | 缺接触格、石子瞬移或姿态身份漂移 FAIL |
| S4 分层合成 | 背景、姿态、道具 → 真 6fps 页面样片 | 角色/罐/石/水各层；固定机位；结果态停留 | 全图缩放冒充人物运动 FAIL |
| S5 中文配音 | 定稿文字、选定授权 TTS/录音 → 两版 8–10s 试听与单独 narration stem | 自然停顿、情绪、发音准确；声源许可明确；人耳试听 | 无可用声源或未试听 BLOCKED，错字/机械腔 FAIL |
| S6 音乐音效 | 情绪曲线 → 独立 music、foley stem、权利台账 | 有可辨旋律与动态；音效位置准确；逐轨试听 | 来源无法证明、混音掩蔽旁白 BLOCKED/FAIL |
| S7 剪辑混音字幕 | 已审素材 → 短样片与最终时间线 | 口播/字/动作同步，响度和峰值合适，无突兀转场 | 不同步、削波、字被 UI 遮挡 FAIL |
| S8 发布级质检 | 解码文件、导演记录 → 六个独立状态、哈希绑定证据 | 技术与视觉/动作/声音/编辑分别签署 | 任一关键项缺证据则 PUBLISH_READY BLOCKED |
| S9 发布工作包 | 已通过视频 → 封面、标题、笔记、版权台账、成片、源文件 | 手机封面和文案实测，权利记录齐全 | 未通过 S8 或缺物料 BLOCKED |

本轮仅完成一段 4 秒单石动作验证，禁止据此扩展整部故事。`TECHNICAL_PASS` 只证明文件规格、解码与非静音；其他状态由各导演实际签发。无自然配音时不降级成机械配音冒充通过。

## R1.1 针对性修复

单石状态机和逐帧审计见 `stone_state.py` 与 `review/stone-audit.json`。每个视频帧只有一个目标石子表示，状态依次为地面、嘴尖接触、夹持、离嘴、罐内下沉、沉底。现有**3 张乌鸦姿态**不能描述完整抬头过程：第 5、9 帧的嘴尖/石子坐标分别跳约 198.49、270.12 px，超过夹持阶段 90 px/帧的审计阈值，`ACTION_PASS` 必须保持 BLOCKED。24 张合成帧从不宣称是 24 张动作原画。

`music-pipeline-test.wav` 是程序正弦波**管线测试素材**，不作为正式背景音乐，也不能取得音乐品质 PASS。`publish_gate.py --scope pilot` 与 `--scope full` 分离；前者即使技术通过也永不能签发 `PUBLISH_READY`，后者必须有完整成片、审核过的旁白/正式音乐/音效、逐轨及总混音的人工试听记录、来源权利文件和混音清单。`KOKORO_ZH_ROUTE.md` 记录正式免费中文 TTS 路线及当前 403 阻断。
